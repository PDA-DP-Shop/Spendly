💬 Cabin Presentation Dialogue (Simple Indian English)

👑 PHONE 1: SPENDLY PERSONAL WALLET APP (Devansh starts)

[Live Action: Devansh welcomes Mam and shows his phone screen running Spendly app]

"Good morning Mam. Today we will show you our project Spendly running live on three mobile phones.

I am holding **Phone 1** with the **Spendly** personal wallet app. Udit has **Phone 2** with the **Spendly Shop** app. And Meet has **Phone 3** with the **Spendly Radar** app.

All these three phones talk to each other directly, peer-to-peer, without using any central server! This protects user privacy and saves monthly hosting costs.

First, look at my phone. The app is locked. When I click **Unlock**, it triggers my phone's fingerprint sensor using the **WebAuthn API**. I touch the sensor, and my local database unlocks.

Now, look at my **Cash note counter**. I can input the exact count of physical notes—like ₹500 or ₹200 notes—and the wallet adds them up instantly.

To receive bills, I use **Air Share**. When Udit completes a transaction on Phone 2, he can beam the bill data to my phone over our local peer-to-peer connection. It imports directly into my local IndexedDB database.

Now, Udit will show you how Phone 2 scans products."
🛒 PHONE 2: MERCHANT POS APP (Udit continues)

[Live Action: Udit shows his phone screen running Spendly Shop POS app]

"Thank you, Devansh. Hello Mam, I am Udit. I am holding **Phone 2** which acts as the shop's billing register.

Meet's phone acts as the store hub. To fetch product prices, I will point my phone camera at this barcode. [Udit scans a barcode]

The register immediately queries Meet's phone over WebRTC, fetches the product details, adds CGST/SGST tax divisions, and compiles the bill.

Now, to send this bill to Devansh, I can use **Air Share**. But we also have two other ways:

First, I can enter the customer's name and mobile number. The app formats the invoice and lets me share it directly to their WhatsApp.

Second, we can print it out on paper. Just like you get a printed receipt at D-Mart, our app connects to a thermal receipt printer and spits out a physical paper bill.

Meet will now explain the store manager dashboard."
📡 PHONE 3: CENTRAL RADAR APP (Meet continues)

[Live Action: Meet shows his phone screen running Spendly Radar app]

"Hello Mam, I am Meet. I have **Phone 3** running **Spendly Radar**.

This is used by store managers to set up stock prices and manage discount campaigns in our local IndexedDB database.

Let's show you how we validate discount coupons. Devansh claims an offer on his app, generating a 6-digit claim PIN. When Udit enters this PIN on the cashier register, it verifies the code with my phone over WebRTC, applies the discount, and updates the stock automatically.

Radar also collects anonymous geocoded transaction coordinates to display sales trend charts without tracking shopper names.

Rudra will now explain how the network connection works."
⛓️ SYSTEM NETWORK INFRASTRUCTURE (Rudra concludes)

[Live Action: Rudra points to the connection logs on the screen]

"Hello Mam, I am Rudra. I will explain the networking behind these three phones.

Since we don't use server databases, the apps communicate directly over **WebRTC DataChannels**.

To establish this peer-to-peer connection, the phones exchange pairing keys using public WebSocket topics on ntfy.sh, meaning we pay $0 in server hosting costs.

We also use a Cloudflare Worker KV storage to look up peer IDs via a temporary 6-digit pairing code.

That concludes our demonstration, Mam. We are happy to answer any questions."

👩‍🏫 Mam's Expected Viva Question Bank (22 Simple Q&As)

Q1. Why are you calling it a "Zero-Knowledge" project?

Because we do not store any customer names, phone numbers, or bills on any internet server. All transactional data stays safely inside the browser's database folder on the user's phone.

Q2. What database did you use and where is it located?

We used **IndexedDB** with the **Dexie.js** library wrapper. The database sits directly inside the web browser's storage space on your phone or computer.

Q3. If there is no backend server, how do the three phones talk to each other?

They talk directly using **WebRTC Peer-to-Peer connection**. We use public WebSocket brokers on ntfy.sh to help the devices share connection keys initially.

Q4. How does the WhatsApp billing share function work?

When Udit enters the customer's name and mobile number, the register formats the invoice details and opens a custom link redirecting to the WhatsApp API to send the text message directly.

Q5. How do you print bills like D-Mart?

The Shop POS app formats receipt sizes using print stylesheets (`@media print`) and connects to thermal printers via Web USB or standard device printer dialogues.

Q6. What is the role of Cloudflare Workers in this project?

Cloudflare Workers KV helps pair registers via a temporary 6-digit connection code. Once the WebRTC connection is opened, we remove the pairing keys from KV storage.

Q7. What is WebAuthn and why did you use it?

WebAuthn is a browser API that lets us lock the local app behind fingerprint or face lock (Passkeys). It generates local decryption keys inside your device's Secure Enclave.

Q8. What is the ntfy.sh WebSocket used for?

WebRTC requires phones to exchange setup messages called SDP keys to connect. Since we have no server, we use ntfy.sh's public WebSocket topics as a mailbox to swap these keys.

Q9. Why React and Vite instead of simple HTML/JS files?

Vite compiles and loads files with hot-reloads during coding, and React lets us write clean component templates to reuse menus, buttons, and lockscreens.

Q10. How does the stock count decrement in Radar on checkout?

When the Shop POS completes checkout, it sends a JSON message packet `STOCK_UPDATE` directly to Radar over the open WebRTC data channel, updating its database counts.

Q11. What is the storage limit of IndexedDB?

Unlike LocalStorage which blocks you after 5MB, IndexedDB has no small limit. It can use up to 50% of your device's free disk space, allowing gigabytes of offline history.

Q12. What is a PWA (Progressive Web App)?

It is a website that behaves like a mobile application. It has a manifest file to let you install it on your home screen, and uses service workers to run offline.

Q13. Why did you separate this project into three apps?

To separate roles. Customer wallets belong to shoppers, registers belong to cashiers, and Radar stock portals belong to managers. They only connect when necessary.

Q14. How does the store credit system work offline?

If checkout is done on credit, the POS register logs it to its local ledger, and beams a credit record to the customer's app, syncing balances without central systems.

Q15. What is the difference between WebSockets and WebRTC?

WebSockets require data to constantly pass through a server relay. WebRTC connects the browsers directly, beaming data directly between phones.

Q16. How does geocoded area analytics work without tracking users?

The User app geolocates coordinates locally (e.g. Mumbai, Powai), strips all personal names or identifiers, and posts transaction totals anonymously to Radar.

Q17. What happens if WebRTC connections fail?

If P2P tunnels fail, the system falls back to dynamic QR code scans or manual 6-digit invoice code typing to complete checkouts.

Q18. Why Zustand instead of Redux?

Redux is complex and requires too much setup code. Zustand is very lightweight, faster, and matches our serverless offline architecture perfectly.

Q19. How does the Cash Counter calculate totals?

It multiplies note counts by note values (₹500 * count500 + ₹200 * count200, etc.) and sums them up locally on the fly.

Q20. What is a Service Worker?

It is a background script that intercepts network queries and serves cached files, allowing the app to run offline even without internet access.

Q21. How do you handle soft deletes in the database?

Instead of deleting records permanently, we flag them with `isSoftDeleted: true` so the user can restore items from a trash bin.

Q22. What library runs the charts on Radar?

We use **Recharts**, which renders clean, responsive SVG analytics curves on screen from IndexedDB arrays.
