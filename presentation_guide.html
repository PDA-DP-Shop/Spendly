👩‍🏫 Mam's Expected Viva Question Bank

Answers in Simple English

Q1. Why are you calling it a zero-knowledge app?

Because there is no central server database hosting user records. All data stays locally inside the browser's origin sandbox on the user's local device. As developers, we cannot read any shopper transaction logs, wallets, or inventories.

Q2. What is IndexedDB and why did you not use simple LocalStorage?

LocalStorage has a storage limit of 5MB and blocks the browser main thread because it runs synchronously. IndexedDB has no strict storage limits (it can utilize gigabytes of disk space) and runs asynchronously, so it doesn't freeze the screen during search queries.

Q3. If there are no servers, how do devices exchange files and messages?

We use WebRTC DataChannels (PeerJS wrapper) to establish direct, peer-to-peer data streams between devices. Handshake signaling is handled by public WebSocket endpoints on ntfy.sh, meaning we don't pay hosting fees.

Q4. How does the clipboard SMS alert parser work without security issues?

Fintech apps ask for system background permissions to read SMS, which is a major privacy risk. In Spendly, the user copies the SMS alert to the clipboard, and our utility parses it locally in memory using regular expressions. No data is sent over the network.

Q5. What happens if the customer doesn't have an internet connection during billing?

The cashier compiles the invoice on the POS Shop app and uses a Web NFC Beam tap, direct WebRTC pairing, or a dynamic QR code on the register screen. The customer can scan the QR code to import the invoice into their database completely offline.

Q6. How does biometric locking work without server databases checking passwords?

We use the browser's native WebAuthn API (Passkeys). The browser communicates directly with the device's hardware Secure Enclave to verify identity. If verified, the app derives decryption keys locally to open the IndexedDB files.

Q7. What is the role of Cloudflare Workers and KV?

They run serverless APIs for two tasks: (1) Storing temporary 6-digit connection pins for WebRTC pairing, and (2) Cloud backups of encrypted stock catalog directories. The pairing pin records delete themselves from KV memory after 10 minutes.
