📱 Spendly User: Consumer Wallet Analysis

Spendly User runs inside the shopper's browser origin sandbox. It manages transaction registers, budget thresholds, cash wallets, and wedding gift folders without contacting external cloud database nodes.

💾 Local Database Tables (IndexedDB)

  • db.expenses: Stores daily transaction history. Fields: category, amount, date, shopName, and isSoftDeleted (enables trash recovery).
  • db.wallets: Tracks available balances. Types: Digital, Card, and Cash Wallets.
  • db.emiAlerts: Schedules monthly EMI triggers. Fields: title, amount, dueDate, isPaid.
  • db.shagunRegistry: Logs wedding and festival cash gift exchanges, maintaining reciprocal balance records.

💵 Cash note counter math

Instead of typing a total cash sum, users enter counts for ₹500, ₹200, ₹100, and ₹50 notes. The app calculates physical cash balances dynamically using note values: 

Balance = (500 * count500) + (200 * count200) + (100 * count100) + (50 * count50)

🔐 WebAuthn Biometric Decryption

Spendly User does not use passwords. Instead, it calls the browser's hardware-backed **WebAuthn API** (Passkeys). Decryption keys are bound directly to the hardware Secure Enclave (Touch ID / Face ID / PIN code) on your phone or PC, ensuring the database remains encrypted on the device when the app is locked.

✉️ Clipboard SMS Regex Utility

Users copy transaction SMS notifications from their bank, and Spendly parses them locally in memory without needing system background SMS permissions:

  • Amount: /(?:Rs\.?|INR|₹)\s*([\d,]+(?:\.\d{2})?)/i
  • Debit check: /(debited|spent|withdrawn|paid)/i
  • Merchant: /(?:at|to|in)\s*([a-zA-Z0-9\s\-]+)/i

🛒 Spendly Shop: Point-of-Sale Register Analysis

Spendly Shop is designed as an offline Point-of-Sale cash register used by cashiers. It handles catalog checks, tax calculations, and billing beam fallbacks entirely peer-to-peer.

📷 Barcode scan & Pricing Queries

The cashier scans product barcodes using the device's camera. The Shop app then sends a `PRODUCT_REQUEST` packet over a direct WebRTC tunnel to the paired Spendly Radar hub. Radar queries its inventory database and returns product descriptions and prices (`PRODUCT_RESPONSE`), allowing the Shop app to build the invoice offline.

⚖️ GST calculations

The POS invoicing engine separates prices into CGST (Central GST) and SGST (State GST) brackets, applies active campaign discounts, and compiles total amounts in a structured receipt object.

⚡ Billing Beam Pipeline (How invoices are shared)

Transport A: Web NFC Beam

Shopper taps their phone on the register screen. The Shop app uses Web NFC to beam the invoice JSON directly to the shopper's device.

Transport B: Direct WebRTC

If devices are already paired, the Shop app encrypts the invoice using AES-256-GCM and transmits it over the open WebRTC data channel.

Transport C: Dynamic QR Code

The register displays a dynamic QR code containing the raw invoice data, which the customer scans with their User app camera.

📡 Spendly Radar: Local Market Hub Analysis

Spendly Radar is run by store managers on a tablet or PC to manage stock catalogs, active promotions, claim codes validation, and local sales trends.

📦 Radar Local Database Schemas

  • db.radarStock: Catalog entries containing barcode values, items description, retail prices, and wholesale purchase costs.
  • db.radarOffers: Catalog of discount campaigns and claim verification codes.
  • db.areaIntelligence: Logs privacy-preserving spending statistics.

🎟️ Offer Claim & Validation PIN Loop

When a user claims an offer, the system generates a 6-digit claim PIN. The cashier inputs the PIN on the POS register, which sends an `OFFER_VALIDATE_REQUEST` to Radar. Radar checks its database, invalidates the code, and confirms the discount.

📊 Privacy-Preserving Area Intelligence Analytics

Spendly compiles local spending trends without exposing user identities. The User app geolocates coordinates locally (e.g. Mumbai, Powai), strips all personal names or identifiers, and posts transaction totals anonymously over randomized sharding topics. Radar logs this data to db.areaIntelligence and displays local chart graphics (built with Recharts).

🔌 P2P Synchronization Matrix

Because Spendly is completely serverless, the sync pathways are split across three network boundaries:

Method 1: Same-Device LocalStorage tab bridge

If apps are opened in tabs on the same browser window, they share states with $0 latency by listening to browser Window 'StorageEvents' on key 'spendly_bridge_msg'.

No Network overhead

Method 2: Cross-Device WebRTC connection

Connects browsers peer-to-peer using WebRTC DataChannels (PeerJS library wrapper) to query product details, redeem coupons, and beam invoices directly.

Direct P2P Data streams

Method 3: ntfy.sh WebSocket Signaling Bridge

WebRTC requires exchanging Session Description Protocol (SDP) configurations. Since there are no custom backend servers, the apps establish WebRTC handshakes by posting encrypted SDP keys over ntfy.sh WebSocket bridge topics (`spendly_bridge_${smallerPeerId}_${largerPeerId}`). Connection integrity is maintained with a 10s ping interval and 25s timeout threshold.

Lightweight Broker Relays

Method 4: Cloudflare Worker Pairing Pins

To pair devices, Radar generates a temporary 6-digit pin and posts it along with its Peer ID to the Cloudflare Worker API. Shop inputs the pin, queries the Worker to retrieve the Peer ID, and deletes the entry from KV storage.

Serverless Matchmaker KV

🚀 Step-by-Step Ecosystem Walkthrough Guide

1

Manager configures inventory stock in Radar

Store owner opens Spendly Radar, enters catalog items (barcode references, retail prices, and wholesale costs) into db.radarStock database.

2

Radar generates a Pairing Code

Radar dashboard generates a temporary 6-character connection code (e.g. `K4N9X3`) and posts it to the Cloudflare Worker API.

3

POS Shop pairs via connection PIN

Cashier enters `K4N9X3` in the POS Shop app. The register queries Cloudflare Workers KV, pulls the matching Peer ID, and establishes a direct WebRTC connection.

4

Shopper reviews available Radar promotions

Shopper opens Spendly User. The app discovers active campaign lists on the local Radar hub.

5

Shopper claims promotional code

Shopper clicks "Claim" on an offer. Radar registers the request and returns a unique 6-digit claim PIN.

6

POS Shop scans barcode labels during checkout

Cashier scans item barcode. Shop POS queries Radar database over WebRTC and fetches item details (`PRODUCT_REQUEST` -> `PRODUCT_RESPONSE`).

7

Redeeming promotional discount

Cashier inputs the shopper's 6-digit claim PIN. Shop POS verifies the code with Radar over WebRTC (`OFFER_VALIDATE_REQUEST`). Radar confirms the code and applies the discount.

8

Updating stock directories

Shop POS sends a stock update packet to Radar, decrementing stock levels for the checked-out items.

9

Billing Beam invoice transmission

Shop POS beams the invoice payload directly to User via Web NFC, WebRTC, or a dynamic QR code on the POS screen.

10

Database Commit

The shopper imports the invoice into their local expenses database.

11

Store credit logging (Credit flow fallback)

If checking out on credit, the transaction is logged to the merchant's local ledger and updated in the customer's personal credit tracking folder.

12

Privacy-Preserving Area Analytics geocodes trends

User app geolocates coordinates locally (e.g. Mumbai, Powai), strips all personal names or identifiers, and posts transaction totals anonymously to display local Recharts sales trend graphs on Radar.
